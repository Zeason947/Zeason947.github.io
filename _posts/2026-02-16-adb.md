# ADB 与 Fastboot 命令完整详细说明（基于最新官方文档，2025-2026 年版本）

本文基于 Android 官方开发者文档（developer.android.com）和常用实践重新整理，结构参考 adb --help 输出顺序，但对每个命令进行完整解释，包括 LOCAL 和 REMOTE 的含义、参数详细作用、实际使用场景和示例。所有解释力求清晰易懂，即使从未使用过也能快速上手。

### 一、ADB 全局参数（Global Options）
这些参数必须放在 adb 命令之后、具体子命令之前，用于控制 ADB 服务器行为或指定目标设备。

adb -a  
作用：让 ADB 服务器监听所有网络接口（不仅仅是 localhost），适用于服务器模式下多网卡环境。  
示例：adb -a devices

adb -d  
作用：强制只操作 USB 连接的物理设备（忽略模拟器），多设备时避免冲突。  
示例：adb -d shell

adb -e  
作用：强制只操作模拟器（忽略物理设备）。  
示例：adb -e install app.apk

adb -s SERIAL  
作用：指定设备序列号（serial number），多设备时必须使用。序列号可通过 adb devices 查看。  
示例：adb -s emulator-5554 shell

adb -t ID  
作用：使用指定的 transport ID（高级选项，内部调试用）。  
示例：较少使用。

adb -H HOST  
作用：指定 ADB 服务器的主机地址（默认 localhost）。  
示例：adb -H 192.168.1.100 devices

adb -P PORT  
作用：指定 ADB 服务器端口（默认 5037）。  
示例：adb -P 5038 start-server

adb -L SOCKET  
作用：指定服务器监听的本地 socket（高级）。  
示例：较少使用。

### 二、常规命令（General Commands）

这些命令属于ADB最基础的部分，主要用于查询连接状态、查看帮助信息和检查版本。它们不修改设备任何设置，仅用于信息获取，是所有ADB操作的起点。即使完全没有经验的用户，也建议先运行这些命令确认环境正常。

adb devices [-l]

作用：列出当前通过ADB服务器连接的所有Android设备（包括物理设备和模拟器）及其当前状态。
这是ADB中最常用的诊断命令之一，在执行任何其他操作前几乎总是先运行它，以确认设备是否正确连接电脑和授权。

参数说明：  
-l 参数会显示更详细的信息，像设备的product（产品变体）、model（型号）、device（设备代号）、transport_id（传输ID）以及USB连接路径等。这些信息在连接多台设备时有用，便于通过 adb -s 指定具体设备。

设备可能出现的状态及其含义：  
device：设备已正常连接、授权并就绪，这是理想状态。注意即使系统尚未完全启动，设备也可能显示此状态。  
offline：设备连接中断或未响应，通常是因为设备忙碌、ADB服务器问题或线缆松动，重启ADB服务器（adb kill-server 和 adb start-server）或重新插拔USB往往能解决。  
unauthorized：设备已通过USB连接但尚未授权ADB调试，此时设备屏幕上会弹出“允许USB调试？”的提示框，需要手动点击允许并勾选“始终允许”。  
recovery：设备当前处于Recovery模式。  
sideload：设备处于ADB sideload模式（用于刷入OTA包）。  
no permissions 或类似提示：权限问题，通常在Linux系统上需要配置udev规则或以root运行。

示例1：基本用法  
命令：adb devices  
典型输出：  
List of devices attached  
emulator-5554	device  
R58M3XXXXXX	device  

示例2：带详细信息  
命令：adb devices -l  
典型输出：  
List of devices attached  
emulator-5554	device product:sdk_gphone_x86_64 model:Pixel_5 device:generic_x86_64 transport_id:1  
R58M3XXXXXX	device product:starlte model:SM-G960F device:starlte usb:2-1.4 transport_id:2  

如果没有设备连接，输出仅为：List of devices attached（下面为空）。

adb help [--all]

作用：显示ADB的完整帮助信息，包括所有支持的命令、全局选项和简要说明。这是快速查看ADB功能的最直接方式，尤其在忘记某个命令具体用法时非常实用。

参数说明：  
不加参数时显示标准帮助（命令列表和简要描述）。  
在某些较新版本中支持 --all 参数，会显示每个命令的更详细解释（如果你的ADB版本较旧可能不支持）。

示例：  
命令：adb help  
输出：会列出所有全局选项、general commands、networking、file transfer 等分类下的命令，格式与 adb --help 完全相同。  
命令：adb --help --all（如果支持）  
输出：每个命令后面会附带更详细的用法说明。

adb version

作用：显示当前电脑上安装的ADB客户端版本信息。如果ADB服务器正在运行，还会显示服务器版本。  
这可以判断是否需要更新ADB（最新版本通常在36.0.x以上，具体取决于Google发布的时间）。

示例：  
命令：adb version  
典型输出（基于2025-2026年常见版本）：  
Android Debug Bridge version 1.0.41  
Version 36.0.2-12345678  
Installed as xxx  
（路径会根据你的操作系统和安装位置不同而变化，Windows通常在 C:\Users\yourname\AppData\Local\Android\Sdk\platform-tools\adb.exe）

这些常规命令是ADB的基石，建议每次开始使用ADB前都先运行 adb devices 确认一切正常，再其他命令

### 三、网络相关（Networking）

这些命令主要用于管理ADB的无线网络连接、端口转发和反向转发，以及mDNS自动发现功能。无线调试是ADB非常实用的特性，尤其在Android 11（API 30）及以上版本中得到了大幅增强，引入了安全的配对机制（pair）和mDNS自动发现，避免了频繁插拔USB线缆。所有无线操作的前提是电脑和设备必须连接到同一个Wi-Fi网络（局域网，企业网络或有防火墙的网络可能阻挡P2P连接，导致失败）。如果你的ADB版本较旧（低于34.x），有些mDNS功能可能无法使用，建议始终使用最新的ADB工具。

adb connect HOST[:PORT]

作用：通过TCP/IP方式无线连接已经配对过的设备。HOST是设备的IP地址，PORT默认是5555（设备在无线调试界面会显示当前端口）。成功后，adb devices 会显示该设备，状态为device，你可以像USB连接一样执行所有ADB命令。

前提条件：在Android 11及以上，必须先使用adb pair完成配对；在Android 10及以下，需要先通过USB执行adb tcpip 5555开启TCP模式，然后才能connect。

示例：  
命令：adb connect 192.168.1.100:5555  
成功输出：connected to 192.168.1.100:5555  
失败常见原因：未配对、网络不同、端口错误、设备无线调试未开启。

常见用法：配对完成后，每次重新开启无线调试或切换网络后，都需要重新执行connect（除非mDNS自动连接成功）。

adb disconnect [HOST[:PORT]]

作用：断开指定的无线连接设备，或者不带参数时断开所有无线连接的设备。断开后，adb devices 将不再显示该设备。

示例：  
命令：adb disconnect 192.168.1.100:5555  
输出：disconnected 192.168.1.100:5555  
命令：adb disconnect  
作用：断开所有TCP/IP设备，常用于清理连接或切换网络时使用。

常见问题：如果断开失败，可以先执行adb kill-server重启ADB服务器再尝试。

adb pair HOST[:PORT] PAIRING_CODE

作用：Android 11及以上版本的无线调试首次配对命令，用于建立安全的加密连接。这是无线调试的核心步骤，配对成功后会保存密钥，后续connect无需再次输入配对码。PAIRING_CODE是设备上显示的6位数字配对码（或通过QR码扫描自动输入）。

前提条件：设备已开启开发者选项 → 无线调试，并在无线调试界面选择“使用配对码配对设备”或“QR码配对”，会显示IP、端口和配对码。

值得注意的是，鸿蒙4.3虽然基于等价安卓12但是无法在设置中启用无限调试。

示例：  
在设备上打开 设置 → 开发者 → 无线调试 → 使用配对码配对设备 → 显示：WLAN配对码：666666，IP地址与端口：192.168.1.100:5555

<img width="1080" height="1920" alt="image" src="https://github.com/user-attachments/assets/f1aa6bdb-ccd9-41d2-a99c-ee4f52675250" />

命令：adb pair 192.168.1.100:5555  
提示输入配对码后(Enter pairing code:)输入666666  
成功输出：Successfully paired to 192.168.1.100:5555 [guid=adb-xxxxxx]

常见问题：配对码只能使用一次，过期后需重新生成；网络阻挡P2P时会失败，此时建议使用USB临时连接或检查路由器设置。

adb forward --list

作用：列出当前所有从电脑端（host）到设备端的端口转发规则。规则会在adb forward命令创建后生效，直到remove或重启ADB服务器。

示例：  
命令：adb forward --list  
典型输出（有多条规则时）：  
emulator-5554 tcp:8080 tcp:8081  
emulator-5554 tcp:9000 localabstract:logd

adb forward LOCAL REMOTE

作用：建立端口转发，将电脑上的LOCAL端口或socket转发到设备的REMOTE端口或socket。这样，你在电脑上访问LOCAL，就相当于直接访问设备的REMOTE。非常适合调试设备上的服务（如Web服务器、数据库等）。

LOCAL和REMOTE支持的类型（协议前缀）：  
tcp:PORT（最常用，例如tcp:8080）  
localabstract:unix_socket_name（Android特有的抽象Unix域套接字）  
localreserved:unix_socket_name  
localfilesystem:unix_socket_path（文件系统路径的Unix域套接字）  
jdwp:PID（Java调试进程ID）  
vsock:CID:PORT（用于虚拟机）  
dev:character_device（字符设备，较少用）

示例：  
命令：adb forward tcp:8080 tcp:8081  
效果：在电脑浏览器访问localhost:8080，就相当于访问设备的8081端口（如果设备运行了Web服务）。  
命令：adb forward tcp:9000 localabstract:logd  
效果：转发到设备的日志守护进程socket，常用于高级日志查看。

常见用法：调试设备上的本地服务器、代理设备网络流量等。

adb forward --remove LOCAL

作用：删除指定的端口转发规则。LOCAL必须和创建时完全一致。

示例：  
命令：adb forward --remove tcp:8080  
成功后该规则消失，可用--list确认。

adb forward --remove-all

作用：一次性删除所有端口转发规则，常用于清理环境。

adb reverse --list / adb reverse REMOTE LOCAL / adb reverse --remove REMOTE / adb reverse --remove-all

作用：反向转发，与forward相反，是将设备的REMOTE端口或socket映射到电脑的LOCAL。这样，设备上访问LOCAL，就相当于访问电脑的对应端口。支持的类型与forward完全相同。

示例：  
命令：adb reverse tcp:8081 tcp:8080  
效果：设备上访问localhost:8081，就相当于访问电脑的8080端口（常用于设备访问电脑上的开发服务器，如Webpack Dev Server）。  
命令：adb reverse --list  
输出类似forward的列表。  
命令：adb reverse --remove tcp:8081  
删除指定规则。  
命令：adb reverse --remove-all  
删除所有反向规则。

常见用法：前端开发时让设备实时预览电脑上的本地网页服务器；设备访问电脑上的代理或调试工具。

adb mdns check

作用：检查当前ADB使用的mDNS（多播DNS）后端是否正常工作。mDNS用于无线调试的自动设备发现（Android 11+）。如果检查失败，自动发现会失效，需要手动输入IP连接。

示例：  
命令：adb mdns check  
成功输出示例：mdns daemon version [Openscreen discovery 0.0.0] 或 mdns daemon version [Bonjour ...]  
失败时提示缺少daemon或不支持。

adb mdns services

作用：列出当前网络中通过mDNS发现的所有ADB无线调试服务（已开启无线调试的设备）。如果一切正常，这里会直接显示设备的服务名，无需手动输入IP。

示例：  
命令：adb mdns services  
典型输出：  
adb-12345678-abcdefg._adb-tls-connect._tcp   192.168.1.100:5555  
看到后可以直接adb connect该IP，或依赖Android Studio自动连接。

常见问题与环境变量：如果mDNS失败，可设置环境变量ADB_MDNS_OPENSCREEN=1切换到Openscreen后端（无需安装Bonjour，适用于Windows/Linux/macOS最新版）。

这些网络命令极大提升了调试效率，推荐优先使用无线调试+mDNS自动发现的组合方式。掌握后，你可以完全摆脱USB线缆进行开发、测试和日志查看。

### 四、文件传输（File Transfer）

这一部分命令主要是用来在电脑和手机之间拷贝文件。adb push 是把电脑上的文件或文件夹送到手机上，adb pull 是从手机上把文件或文件夹拉到电脑上。这两个命令超级实用，比如备份照片、传视频、安装文件什么的，都靠它们。adb sync 是给开发Android系统的人用的，普通用户基本用不到，我们简单说一下就好。所有这些操作都需要手机已经连上ADB，并且授权过了（adb devices 显示 device 状态）。

adb push LOCAL REMOTE

作用：把电脑上的文件或者整个文件夹推送到手机上。简单说，就是从电脑“发”东西到手机。

LOCAL 是电脑上的文件路径。你可以写相对路径（比如 ./myfile.txt，表示当前文件夹下的文件），或者绝对路径（比如 C:\Users\你的名字\Desktop\video.mp4）。支持单个文件，也支持整个文件夹（会自动把文件夹里所有东西都传过去）。

REMOTE 是手机上的目标路径。必须是手机允许写入的地方。最常见的是 /sdcard/ 开头的路径，因为这是手机的内部存储，相当于手机的文件管理器里能看到的存储空间。比如 /sdcard/Download/（下载文件夹）、/sdcard/DCIM/Camera/（相机照片文件夹）、/sdcard/Movies/（视频文件夹）。注意：有些系统目录（如 /system/）默认不能写，需要手机已经root或者用 adb remount 才能操作。

常用参数：  
--sync 参数：只传输有变化的文件。如果之前传过同样的文件夹，再次用 --sync 只会更新改动过的文件，速度更快，适合频繁同步大文件夹。  
-n 参数：模拟一下传输过程，看看会传哪些文件，但实际上不真的传。用来检查路径对不对，很安全。  
-z 参数：开启压缩，传输大文件时能省流量和时间（无线连接时特别明显）。  
-Z 参数：关闭压缩（默认是开的，如果你不想压缩就用这个）。

示例：  
命令：adb push ./photo.jpg /sdcard/Download/photo.jpg  
效果：把电脑当前文件夹下的 photo.jpg 传到手机的Download文件夹。  
命令：adb push ./Music /sdcard/Music  
效果：把电脑上的 Music 文件夹整个传到手机的Music文件夹（会自动创建文件夹）。  
命令：adb push --sync ./bigfolder /sdcard/bigfolder  
效果：只更新 bigfolder 里改动过的文件，其他不变。  
命令：adb push -n ./test.txt /sdcard/test.txt  
效果：只显示会传输什么，但不真的传。

常见问题：如果提示 “Read-only file system”，说明目标路径不能写，需要用 adb root 和 adb remount（仅限有root权限的手机）。传输中断可以重新运行命令，它会继续传没传完的部分。

adb pull REMOTE LOCAL

作用：从手机上拉取文件或者整个文件夹到电脑。简单说，就是从手机“拿”东西到电脑。最常用的是备份照片、视频、下载的文件。

REMOTE 是手机上的源路径，和 push 的 REMOTE 一样，用 /sdcard/ 开头的最安全。

LOCAL 是电脑上的目标路径。可以不写（默认拉到电脑当前文件夹），也可以指定文件夹。如果拉的是文件夹，会自动创建对应的文件夹结构。

常用参数：  
-a 参数：保留文件的创建时间和权限（比如照片的拍摄时间会保持原样，拉到电脑后还是原来的日期）。

示例：  
命令：adb pull /sdcard/Download/myvideo.mp4 ./  
效果：把手机下载文件夹里的 myvideo.mp4 拉到电脑当前文件夹。  
命令：adb pull /sdcard/DCIM/Camera ./PhonePhotos  
效果：把手机相机里的所有照片和视频整个拉到电脑新建的 PhonePhotos 文件夹里（超级适合备份照片）。  
命令：adb pull -a /sdcard/Download/report.pdf C:\Backup\  
效果：拉取文件并保持原文件的日期和属性，保存到电脑的 Backup 文件夹。

常见问题：如果文件很大，拉取时间会比较长，无线连接比USB慢很多，建议用USB线。提示 “No such file or directory” 就是路径写错了，用 adb shell ls /sdcard/ 先检查手机上到底有什么文件。

adb sync

作用：这是给开发Android系统的人用的，把电脑上编译好的系统文件快速同步到手机的分区里（比如 system、vendor、product 等分区）。它比 push 更聪明，只同步有变化的文件，速度非常快。

普通用户基本用不到，除非你在自己编译AOSP源码并刷到手机上测试。

用法：adb sync [分区]，比如 adb sync system 会把编译好的 system 分区文件同步到手机。

如果你不是开发者，完全可以忽略这个命令。

总结一下：文件传输最常用的就是 push 和 pull，记住 /sdcard/ 是手机内部存储的根目录，几乎所有个人文件都在这里。备份照片用 pull 相机文件夹，传电影到手机用 push，大文件建议用USB线，速度快很多。掌握了这两个命令，你就能轻松在电脑和手机之间来回拷贝东西了。

### 五、Shell 相关

这一部分命令是ADB里最强大也最常用的功能之一。简单说，adb shell 就是让你在电脑上直接操作手机的命令行，就像在手机上打开一个终端窗口一样。你可以用它查看文件、运行程序、检查进程、修改设置，几乎什么都能干。只要手机连上ADB并且授权了，这些命令就能用。普通用户可以用它列文件、截屏、录屏，开发者可以用它调试应用、查看日志，玩机爱好者可以用它执行各种高级操作。

adb shell

作用：直接进入手机的交互式命令行环境。运行这个命令后，你的电脑命令提示符会变成手机的shell，你输入的每一条命令都会在手机上执行，结果也显示在电脑上。想退出就输入 exit 或者按 Ctrl+D。

这超级适合需要连续执行多条命令的时候。比如你想一步步查看手机文件、复制东西、运行程序，都可以在这里慢慢操作。

示例：  
命令：adb shell  
进入后提示符变成类似 $ 或 #（如果是root就是#）  
然后你可以输入：ls /sdcard/  查看手机存储里的文件  
输入：ps  查看正在运行的程序  
输入：top  实时看手机CPU和内存占用  
输入：exit  退出回到电脑的命令行

常见场景：想在手机上跑几条命令测试，比如检查某个文件存不存在、杀掉一个卡住的程序，都用这个。

adb shell COMMAND

作用：不用进入交互模式，直接在电脑上运行一条手机命令，然后把结果显示出来就结束。适合只想快速执行一条命令，不想进进出出的情况。

COMMAND 就是你要跑的那条命令，几乎所有Linux命令手机都支持（因为Android基于Linux），比如 ls（列文件）、cd（切换目录）、cat（查看文件内容）、rm（删除文件）、mkdir（创建文件夹）等等。

示例：  
命令：adb shell ls /sdcard/Download  
效果：直接显示手机下载文件夹里的所有文件和文件夹名字  
命令：adb shell df -h  
效果：显示手机存储空间使用情况，像磁盘分区大小和剩余空间  
命令：adb shell pm list packages  
效果：列出手机上安装的所有应用包名（超级有用，想卸载系统应用时先查包名）  
命令：adb shell dumpsys battery  
效果：查看当前电池信息，比如电量、温度、充电状态  
命令：adb shell screencap /sdcard/screenshot.png  
效果：在手机上截一张屏，保存到 /sdcard/screenshot.png  
然后你可以用 adb pull 拉到电脑：adb pull /sdcard/screenshot.png ./

还有录屏：adb shell screenrecord /sdcard/demo.mp4  （录3分钟自动停，按Ctrl+C手动停）

这个方式是最常用的，因为大多数时候你只想快速查点东西或跑一条命令。

常见参数（这些参数不常用，普通用户可以先跳过，高级时再看）：  
-e：设置特殊的转义字符，主要用来处理命令里有引号或特殊符号时避免出错。  
-n：不从电脑读取任何输入，适合脚本里用，避免意外卡住。  
-T：禁用伪终端，有些命令不需要交互界面时用，能让输出更干净。  
-t：强制给命令分配一个伪终端，有些需要交互的命令必须加这个才会正常运行。  
-x：禁用远程退出码的分离，高级脚本用得多。

举个带参数的例子：  
命令：adb shell -t -t am start -a android.intent.action.VIEW -d https://www.baidu.com  
效果：强制分配终端，打开手机浏览器访问百度（某些启动命令需要-t）。

adb emu COMMAND

作用：专门给Android模拟器用的，向模拟器发送一些特殊控制命令。比如旋转屏幕、模拟来电、发短信、改变位置什么的。

普通手机用户基本用不到，因为这是针对电脑上跑的模拟器（emulator）设计的。如果你用的是真手机，这个命令几乎没用。

示例：  
命令：adb emu geo fix 116.3 39.9  
效果：在模拟器里设置当前位置为北京（经纬度）  
其他常见：adb emu kill  杀掉模拟器进程

总结一下：Shell命令是ADB的灵魂，学会了 adb shell + 一些基本Linux命令，你就能在电脑上完全控制手机的文件和很多设置了。开始可以多试试 ls、cd、cat、pm、am、dumpsys这些常用命令，慢慢就熟练了。记住大部分操作都在 /sdcard/ 目录下最安全，不会轻易搞坏系统。

### 六、应用安装管理

这一部分命令主要是用来在手机上安装或者卸载应用的。adb install 是把一个APK文件安装到手机上，adb install-multiple 是安装那种拆分成多个文件的应用（比如谷歌Play商店里的大应用），adb uninstall 是卸载应用。这些命令特别实用，比如你从网上下载了个APK想试试，或者想删掉手机上某个烦人的预装应用，都可以用它们。前提是手机已经连上ADB，并且开启了USB调试（或者无线调试）。

adb install PACKAGE.apk

作用：把电脑上的一个APK文件安装到手机上。PACKAGE.apk 就是APK文件的路径，可以是相对路径（比如 myapp.apk，在当前文件夹）或者完整路径（比如 C:\Download\game.apk）。安装成功后，应用就会出现在手机的应用列表里。

常用参数（这些参数可以组合用，比如 -r -t 一块写）：  
-r 参数：覆盖安装，也叫替换安装。如果手机上已经有个同名的应用，用 -r 就会直接覆盖旧版本，但会保留旧版本的数据和设置（比如游戏进度不会丢）。不加 -r 的话，如果版本一样或更低，会提示已经安装了。  
-t 参数：允许安装测试包。有些APK是标记为“测试用”的（android:testOnly="true"），正常情况下手机不让装，加 -t 就能强行安装。开发者测试应用时常用。  
-d 参数：允许版本降级。正常安装时，新APK的版本号必须比手机上已装的高才行，加 -d 就能装低版本的（比如想回滚到旧版）。  
-g 参数：安装完自动给应用所有运行时权限（比如相机、存储、位置这些）。省得安装后一个个手动开权限。  
--streaming 参数：用流式方式安装，适合特别大的APK文件（几百MB甚至GB级），它一边传文件一边安装，内存占用小，速度也更快。普通小文件不用加。  
还有其他参数（新版ADB常见）：  
--incremental 参数：增量安装，需要手机支持（Android 12+），速度超快，但普通用户很少用。  
--bypass-low-target-sdk-block 参数：绕过低SDK版本限制（某些旧应用在新系统上被挡）。

示例：  
命令：adb install C:\Download\myapp.apk或adb install myapp.apk  
效果：普通安装，如果已经有了就失败。直接跟文件名需要文件在当前文件夹下。下面命令同理  
命令：adb install -r game.apk  
效果：覆盖安装，保留你的游戏存档。  
命令：adb install -r -t -g debug_app.apk  
效果：覆盖安装测试包，还自动给所有权限。  
命令：adb install --streaming biggame.apk  
效果：流式安装大文件，不会卡顿。

常见问题：安装失败提示 “INSTALL_FAILED_ALREADY_EXISTS” 就加 -r；提示版本低就加 -d；大文件卡住试试 --streaming；如果提示签名不一致，通常是新旧APK签名不同，没法覆盖，只能先卸载再装。

adb install-multiple APK1 APK2 ...

作用：安装拆分APK，也叫App Bundle（谷歌现在很多应用都用这种格式，一个应用拆成几个文件：base.apk + split_xxx.apk）。你需要把所有拆分文件都列出来，一起安装。工具像Split APKs Installer（SAI）也能干这个，但用ADB更直接。

示例：  
命令：adb install-multiple base.apk config.xx.apk config.zh.apk  
效果：把一个拆分成多个文件的应用完整安装好。

还有个类似命令 adb install-multi-package（新版才有），功能差不多，但可以把多个完全独立的应用当成一个事务一起安装，失败就全滚回。

普通用户下载APK时大多是单个文件，用install就够了，拆分包的情况少。

adb uninstall PACKAGE

作用：卸载手机上的应用。PACKAGE 是应用的包名（比如 com.tencent.mm 是微信，com.android.chrome 是Chrome浏览器）。怎么查包名？用 adb shell pm list packages 查看所有，或者去应用信息里看（设置-应用-点击应用-高级）。

常用参数：  
-k 参数：卸载应用但保留数据和缓存。比如卸载游戏但想留存档，下次装回来还能继续玩。

示例：  
命令：adb uninstall com.example.myapp  
效果：完全卸载应用，连数据一起删。  
命令：adb uninstall -k com.tencent.mm  
效果：卸载微信，但聊天记录和缓存还在，下次装回来可能还能用（视应用而定）。

常见问题：系统应用卸载会提示失败，除非手机root了或者用 adb shell pm disable-user（禁用但不卸载）。卸载失败可以试试重启手机或ADB服务器。
不建议卸载系统应用

总结一下：安装应用最常用 adb install -r（覆盖装，保留数据），卸载用 adb uninstall -k（保留数据）。包名记不住就先用 adb shell pm list packages | grep 关键词 搜一下。侧载APK（非官方商店安装）就靠这些命令了，简单又快，还能处理权限和版本问题。

### 七、调试命令（Debugging）

这一部分命令主要是帮你排查手机问题、查看日志、调试应用的。开发者用得最多，但普通用户遇到手机卡顿、应用崩溃、系统异常时，也可以用这些命令抓日志发给开发者或者自己分析。它们不会修改手机任何东西，只是读取信息，所以用起来很安全。前提还是手机连上ADB并且状态正常。

adb bugreport [PATH]

作用：让手机生成一份完整的“体检报告”，里面打包了几乎所有系统信息：日志、运行中的进程、内存使用、电池状态、网络连接、已安装应用列表、系统设置等等。超级全面，就像给手机做了一次大检查。生成的文件是个zip包，里面有很多txt文件和xml文件，你可以用电脑解压查看，或者直接发给别人帮忙看问题。

PATH 是可选的，用来指定报告保存到电脑的哪个文件夹。如果不写PATH，默认会直接在电脑当前文件夹生成一个叫 bugreport-日期-时间.zip 的文件。

示例：  
命令：adb bugreport  
效果：手机上会显示“Generating bugreport...”进度条，几分钟后（视手机性能而定）完成，电脑上出现 bugreport.zip 文件。  
命令：adb bugreport C:\Backup\mybugreport.zip  
效果：指定保存路径和文件名（如果路径不存在会出错，所以确保文件夹存在）。

常见场景：应用闪退了，开发者让你“抓个bugreport”；手机发热卡顿，想自己看看日志；刷机出问题了，发报告给刷机包作者。报告很大（几十MB到上百MB），生成时手机会稍微卡一下，建议连USB别动它。

小提示：新版Android（Android 10+）的bugreport生成更快，还包含更多信息。如果你只想看部分日志，用logcat就够了，不用这么大份报告。

adb jdwp

作用：列出手机上当前所有支持JDWP调试的进程。JDWP是Java Debug Wire Protocol的缩写，简单说就是Android应用（用Java或Kotlin写的）运行时会有一个调试端口，这个命令就是把这些端口对应的进程ID（PID）列出来。

这个命令用得少，主要给开发者在用Android Studio或者其他工具调试应用时，用来确认哪些进程可以attach调试器。

示例：  
命令：adb jdwp  
输出：一串数字，每行一个PID，比如  
1234  
5678  
意思是进程1234和5678支持JDWP调试。

普通用户基本用不到，除非你在学Android开发，想手动调试应用。一般都是Android Studio自动处理。

adb logcat

作用：实时查看手机的系统日志。Android系统里所有东西（系统、应用、驱动）运行时都会往日志里写信息，比如应用崩溃了会写错误，系统启动会写启动过程，网络连接会写连接状态。logcat就是把这些日志实时打印到电脑屏幕上，像一条条滚动的信息流。

这是ADB里最最常用的调试命令，开发者离不开它，玩机爱好者也常用它看问题。

基本用法：直接运行 adb logcat，日志就会刷屏一样滚出来，按Ctrl+C停掉。

常用过滤参数（这些参数可以让你只看想看的内容，不然信息太多看不过来）：  
*:V  显示所有详细（verbose）级别日志（信息最多，最吵）。  
*:D  只显示Debug及以上。  
*:I  只显示Info及以上。  
*:W  只显示Warning及以上（警告）。  
*:E  只显示Error及以上（错误，最常用，看崩溃就用这个）。  
*:F  只显示Fatal（致命错误）。  

还可以按标签过滤，比如 AndroidRuntime:E 显示运行时错误，ActivityManager:I 显示应用启动信息。

清空日志：adb logcat -c （清空后重新开始记录）。  
保存日志到文件：adb logcat > log.txt （在电脑当前文件夹保存，按Ctrl+C停）。  
带时间戳：adb logcat -v long （每条日志带完整时间）。

示例：  
命令：adb logcat *:E  
效果：只显示错误日志，应用崩溃时这里会刷出红色的错误信息和堆栈。  
命令：adb logcat -s MyAppTag  
效果：只显示标签是MyAppTag的日志（开发者在代码里打的tag）。  
命令：adb logcat | grep "crash"  
效果：实时搜索包含“crash”的日志行（结合Windows的findstr或者mac/Linux的grep）。  
命令：adb logcat -c && adb logcat > crashlog.txt  
效果：先清空日志，然后开始记录保存到文件，复现问题后停掉，就得到干净的崩溃日志。

常见场景：应用闪退了，用 *:E 看错误原因；手机重启了，看启动日志找问题；电池耗电快，看power相关的日志。

小提示：日志刷得太快看不清，可以加过滤，或者保存到文件再慢慢看。用Android Studio的Logcat界面更友好，有颜色和高亮。

总结一下：调试命令里 logcat 是日常王者，bugreport 是大招（问题严重时用），jdwp 是专业开发者专属。学会 logcat 基本过滤，你就能自己抓到大部分应用崩溃的原因，发给开发者或者上网搜错误信息基本能解决问题。

### 八、安全相关
adb disable-verity / enable-verity  
作用：关闭或开启 dm-verity 检查（仅 userdebug 构建，需要 root）。

adb keygen FILE  
作用：生成 ADB 密钥对（用于无线调试安全连接）。

### 九、脚本控制（Scripting）

这一部分命令大多是为写自动化脚本设计的，比如用批处理文件（Windows的.bat）或者shell脚本（Linux/mac的.sh）来批量操作手机。但普通用户也能直接用，它们能帮你等待设备连接、查设备信息、重新挂载分区、重启到特殊模式、刷OTA包、切换root权限或者无线模式。这些命令特别适合刷机、恢复系统、自动化测试的时候用。有些命令需要手机有root权限，或者是工程机（eng/userdebug构建），普通手机不一定全都能用。

adb wait-for-device

作用：让命令暂停等待，直到手机完全连上ADB并且状态正常（device状态）。在脚本里超级有用，因为脚本跑得快，如果设备还没准备好，后面的命令就会失败，加这个就能等它上线。

示例：  
命令：adb wait-for-device  
效果：卡在这里不动，直到adb devices显示device状态才继续。  
脚本里常用：adb wait-for-device && adb root && adb remount  
意思是等设备好了再一步步执行后面的命令。

常见场景：开机后自动跑一堆命令，或者刷机脚本里等手机重启完成。

adb get-state

作用：快速查手机当前连接状态，返回一行字：device（正常）、offline（断开）、recovery（恢复模式）之类的。

adb get-serialno

作用：返回手机的序列号（serial number），就是adb devices里那一串数字或字母。

adb get-devpath

作用：返回手机的设备路径（USB路径之类的），高级调试用。

这三个命令都很简单，主要是脚本里用来判断或记录设备信息。

示例：  
命令：adb get-state  
输出：device  
命令：adb get-serialno  
输出：R58M3XXXXXX  

普通用户偶尔用来看看状态，脚本里用得多。

adb remount

作用：把手机的系统分区（/system）重新挂载成可读可写模式。正常情况下系统分区是只读的，想改系统文件就得先remount。必须手机已经root，并且adbd以root运行才行（用adb root先开启）。

-R 参数：remount失败时自动重启手机再试（有些手机需要重启才能生效）。

示例：  
命令：adb root  
命令：adb remount  
成功输出：remount succeeded  
然后你就能push文件到/system了，比如adb push newfile.txt /system/etc/

常见问题：普通零售手机没root，这个命令会失败。提示“remount failed”就说明权限不够。

刷机爱好者常用这个改系统文件，比如替换hosts、加模块。

adb reboot [bootloader/recovery/sideload]

作用：重启手机到不同模式。不写参数就是普通重启到系统。

加 bootloader：重启到fastboot模式（刷底层分区用）。  
加 recovery：重启到恢复模式（刷机、擦除数据）。  
加 sideload：重启到sideload模式（专门用来刷OTA包）。

示例：  
命令：adb reboot  
效果：普通重启。  
命令：adb reboot bootloader  
效果：重启进fastboot，屏幕显示fastboot模式。  
命令：adb reboot recovery  
效果：进recovery菜单。

这是刷机最常用的重启命令。

adb sideload OTA.zip

作用：在recovery模式的sideload状态下，刷入官方OTA升级包。比直接刷zip安全，不会改错分区。

用法：先adb reboot sideload进入模式，或者手动进recovery选Apply update from ADB，然后运行这个命令。

示例：  
命令：adb sideload update.zip  
效果：进度条显示传输和验证，完成后自动重启升级。

官方升级不想解锁bootloader时用这个最安全。

adb root

作用：重启adbd守护进程，让它以root权限运行。这样后面的命令就能有root权限了（比如remount、push到system）。

adb unroot

作用：相反，关闭root模式，回到普通权限。

注意：只有工程机（eng或userdebug构建）才支持，普通用户手机会提示“adbd cannot run as root in production builds”。

示例：  
命令：adb root  
输出：restarting adbd as root  
然后adb shell里提示符变成#（root标志）。

开发者机或刷机后的手机常用。

adb usb

作用：把无线调试切换回USB模式（如果之前是tcpip模式）。

adb tcpip PORT

作用：把ADB切换到无线TCP模式，监听指定端口（通常5555）。切换后就能拔线用无线了。

示例：  
先用USB连上：adb tcpip 5555  
输出：restarting in TCP mode port: 5555  
然后拔线：adb connect 192.168.1.100:5555  
就能无线用了。

要切回USB：adb usb

无线调试的基础命令。

总结一下：这些命令让ADB能写脚本自动化操作，比如一键重启进fastboot、一键刷OTA、一键remount改系统。普通用户最常用reboot和sideload，玩机高手会结合root和remount改系统。记住很多命令需要root或工程机构建，普通手机用不了root相关的。

### 十、内部调试
adb start-server / kill-server  
作用：手动启动或关闭 ADB 服务器。

adb reconnect / reconnect device / reconnect offline  
作用：强制重新连接设备或清理离线设备。

### 十一、Fastboot 常用命令（Bootloader 模式）

Fastboot 是手机进入 Bootloader 模式后才能用的命令工具。它比 ADB 更底层，直接操作手机的分区、镜像和启动设置。简单说，就是用来刷机、解锁 bootloader、临时测试镜像这些高级操作的。普通用户很少碰，除非你想刷第三方 recovery、root 手机、刷自定义 ROM 或者救砖。操作前一定要备份数据，因为很多命令会擦掉手机所有东西。fastboot 命令和 adb 在同一个 platform-tools 文件夹里，用法类似，直接在电脑命令行输入 fastboot 加参数。

先说怎么进入 Fastboot 模式：  
最简单的方式是用 ADB：adb reboot bootloader （手机连上 ADB 后运行这个，手机就会重启进 Fastboot）。  
或者关机状态下按硬件键：不同品牌手机组合不一样，比如小米是音量下 + 电源键，谷歌 Pixel 是音量下 + 电源键，华为是音量上 + 下 + 电源键（具体查你手机型号）。进入后屏幕通常会显示 “FASTBOOT MODE” 或类似字样。

所有 fastboot 命令都需要手机在 Fastboot 模式下，并且用 USB 线连电脑（无线不支持）。

fastboot devices

作用：检查有没有手机正确连上 Fastboot 模式。类似 adb devices，是你运行其他 fastboot 命令前必须先确认的步骤。

示例：  
命令：fastboot devices  
输出：一串序列号 fastboot （比如 12345678 fastboot）  
如果没输出，说明没连上，试试换线、换端口、重启电脑或者重新进 Fastboot。

fastboot flashing unlock

作用：解锁 bootloader（引导加载程序）。解锁后你才能刷第三方镜像、root 手机。解锁会擦掉手机所有数据（相当于出厂恢复），所以提前备份。解锁后手机安全功能会变弱，开机可能有警告提示，有些银行 App 可能不让用。

示例：  
命令：fastboot flashing unlock  
手机屏幕会弹出确认提示，用音量键选到 Yes，然后按电源键确认。成功后输出 finished。

fastboot flashing lock

作用：重新锁定 bootloader。锁定后手机恢复官方状态，有些功能（如银行支付）能正常用。但如果你刷过第三方东西，锁定可能导致砖机，所以一般刷完自定义 ROM 后别锁。

示例：  
命令：fastboot flashing lock  
同样需要手机屏幕确认，也会擦除数据。

注意：新款手机（Android 9 以后很多）用 flashing unlock/lock，老款可能还用下面的 oem unlock。

fastboot oem unlock KEY

作用：老设备解锁 bootloader 的命令，需要 KEY（解锁码）。有些厂家（如小米、华为旧机）要先在官网申请解锁码，绑定账号等几天才能拿到一串码。

示例：  
命令：fastboot oem unlock 你的解锁码  
比如 fastboot oem unlock 1234567890ABCDEF

现在很多新手机已经不用这个了，直接用 flashing unlock。

fastboot flash 分区 镜像文件

作用：把电脑上的镜像文件刷写到手机指定分区。这是刷机最核心命令，比如刷 recovery、boot、system 分区。

常见分区：boot（内核）、recovery（恢复）、system（系统）、vendor（厂商）、bootloader（引导）、radio（基带）等。

示例：  
命令：fastboot flash recovery twrp.img  
效果：把 twrp.img 刷到 recovery 分区，下次进 recovery 就是 TWRP 了。  
命令：fastboot flash boot magisk_patched_boot.img  
效果：刷一个打了 Magisk 补丁的 boot 镜像，实现 root。

镜像文件（.img）通常从官网或第三方下载，文件名要对得上分区。

fastboot erase 分区

作用：擦除指定分区的内容。比如擦 userdata 相当于恢复出厂。

fastboot format 分区

作用：格式化分区（和 erase 差不多，但有些设备 format 更彻底）。

示例：  
命令：fastboot erase userdata  
效果：擦掉所有用户数据。

fastboot boot 镜像文件

作用：临时启动一个镜像文件，不真正刷写到手机。超级安全，用来测试新 recovery 或新内核好不好用，不行重启就恢复原样。

示例：  
命令：fastboot boot twrp.img  
效果：手机直接启动到这个 twrp recovery，重启后又变回原来的。

测试新东西必备命令。

fastboot getvar all

作用：查看手机所有变量信息，比如是否解锁（unlocked）、当前槽位（a 或 b）、产品型号、序列号等。非常有用，刷机前刷机后对比一下。

示例：  
命令：fastboot getvar all  
输出：一大堆行，比如 unlocked: yes、current-slot: a 等。

fastboot set_active a

或者 fastboot set_active b

作用：切换 A/B 分区槽位。新款手机（支持无缝更新）有两个系统槽位 a 和 b，升级时刷到另一个槽位。切换后重启就用指定的槽位启动。救砖时常用，如果一个槽位坏了切到另一个。

示例：  
命令：fastboot set_active b  
然后 fastboot reboot 就启动 b 槽位。

fastboot reboot

作用：从 Fastboot 模式重启到正常系统。

示例：  
命令：fastboot reboot  
手机就正常开机了。

总结一下：Fastboot 是刷机玩机的核心工具，解锁 bootloader 是第一步（flashing unlock），然后 flash 各种分区，boot 临时测试。操作前一定要看清手机型号和对应教程，因为刷错分区可能直接砖机。建议新手先多看官方指南或 XDA 论坛的教程，一步步来。玩 Fastboot 时保持 USB 连接稳定，别中途拔线。


### 结论
ADB 用于系统运行时的调试、文件传输、应用管理。  
Fastboot 用于 Bootloader 模式下的底层刷写。  
掌握这些命令后，可实现无线调试、端口映射、文件传输、应用安装卸载、系统日志查看、OTA 刷入、Bootloader 解锁、A/B 分区切换等完整操作。
